### 4.3 `.npmrc` (NEW)

```
node-linker=hoisted
public-hoist-pattern[]=*react-native*
public-hoist-pattern[]=*expo*
public-hoist-pattern[]=*metro*
public-hoist-pattern[]=*@babel/runtime*
shamefully-hoist=false
auto-install-peers=true
strict-peer-dependencies=false
```

Rationale:
- `node-linker=hoisted`: Expo monorepos require this; strict isolation breaks RN native modules.
- `public-hoist-pattern[]`: hoists Expo/RN/Metro to workspace root so each app can resolve them.
- `auto-install-peers=true`: pnpm-specific quirk — Expo has peer deps that need explicit install otherwise.
- `strict-peer-dependencies=false`: tolerates Expo's somewhat loose peer dep declarations.

## 5.4 Special handling — `supabase/functions/_shared/eventTaxonomy.ts`

Deno edge functions cannot consume pnpm workspaces. They use URL-style imports (`https://deno.land/...`) or local paths within `supabase/functions/`. The `_shared/eventTaxonomy.ts` file must stay where it is.

To prevent drift between the package and the Deno copy:

1. Keep `supabase/functions/_shared/eventTaxonomy.ts` as a manual mirror.
2. Add a header comment at the top of BOTH `packages/event-taxonomy/src/index.ts` AND `supabase/functions/_shared/eventTaxonomy.ts`:
   ```ts
   /**
    * ORCH-0826: this file has two copies — one in
    * `packages/event-taxonomy/` (consumed by Expo apps) and one in
    * `supabase/functions/_shared/` (consumed by Deno edge functions).
    * Keep them byte-equivalent. CI gate `orch-0826-event-taxonomy-mirror.mjs`
    * enforces.
    */
   ```
3. Add a new CI gate `orch-0826-event-taxonomy-mirror.mjs` that diffs the two files. (Simpler than the previous 3-way gate.)
4. Update workflow registration: remove the old orch-0824 parity gate, add the new orch-0826 mirror gate.

This is the minimum-coupling solution. The 2-way mirror still requires CI enforcement but is only one place to forget (mirror script) rather than three.
