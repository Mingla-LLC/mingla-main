3. THE GORHOM BLOCKER (why onboarding CANNOT reuse the wrapper as-is)
════════════════════════════════════════════════════════════════════════
Onboarding host chrome: app-mobile/src/components/onboarding/OnboardingShell.tsx
  :271 SafeAreaView → :272 KeyboardAwareView → :287 plain RN <ScrollView>.  NO @gorhom/bottom-sheet.
gorhom version: @gorhom/bottom-sheet ^5.2.8 (package.json).
  - BottomSheetScrollView (v5) consumes the sheet's internal scroll-gesture context via
    useBottomSheetInternal() → THROWS ("BottomSheetInternalContext not found") when rendered
    OUTSIDE a <BottomSheet>. The consumer wrapper hardcodes it (:246), so dropping the wrapper
    into the onboarding screen (LIGHT_TOKENS → dropdown.mode "card" → the field wraps rows in
    ScrollComponent, shared component :516) would HARD-CRASH.
  - Precedent for the correct pattern: the shared component's own doc (:24) — "The business host
    OMITS TextInputComponent → falls back to RN TextInput." Non-sheet hosts OMIT the gorhom
    injections. Onboarding = same situation.
  ⇒ The consumer wrapper must gain an optional `inBottomSheet` flag (default true) that, when
    false, OMITS both gorhom injections so the shared field uses plain RN TextInput + ScrollView.
