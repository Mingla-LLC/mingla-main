# ORCH-0763A Publish Draft Slug and Share Link Audit

Date: 2026-05-08
Mode: Forensics / investigation
Verdict: FAIL - the domain deploy is fixed, but publish still promotes a draft URL identity into the public event link.

## Executive Summary

The user's new symptom is confirmed.

Mingla Business currently creates a server draft with a temporary slug based on the word `draft`, for example `draft-nlhj`. The database then freezes event slugs at creation. When the organiser publishes, the publish code preserves that draft slug instead of replacing it with a final event slug based on the event name. The local published event, public route, share modal, QR code, SEO canonical URL, and checkout back-links all inherit that bad slug.

Live read-only production evidence confirms one public scheduled event:

```text
brand_slug: leggothis
slug: draft-nlhj
title: Visa
status: scheduled
visibility: public
published_at: 2026-05-08T18:48:35.256+00:00
free ticket: The free, price_cents 0
```

The route `https://business.usemingla.com/e/leggothis/draft-nlhj` returns the app shell, so the latest deploy did fix cold route delivery. The problem is now URL identity and link UX, not Vercel routing.

## Scope

Audited:

- Draft creation and server slug creation.
- Publish flow.
- Local live-event conversion.
- Public event route and public event service.
- Step 7 "Tickets will go live at..." card.
- Share modal behavior.
- Events schema, unique slug index, and immutable slug trigger.
- Current ORCH-0759/ORCH-0763 reports/specs.
- Live read-only public Supabase REST evidence via anon public view and ticket reads.

No product code was changed in this investigation.

## Confirmed Findings

### F1 - Server drafts are created with `draft-*` slugs

Severity: P0 launch blocker.

Evidence:

- `mingla-business/src/services/eventDrafts.ts:19-20`:

```ts
const serverDraftSlug = (): string =>
  generateEventSlug("draft", new Set<string>());
```

- `createServerDraft` passes that slug into `draftToServerInsert`.
- Current production public view shows a published event with slug `draft-nlhj`.

Current behavior:

The first durable `events.slug` for a server-backed draft is not event-name-based. It is a random `draft-*` placeholder.

Expected behavior:

A public published event should have a durable public slug derived from the final publishable event identity, such as `visa-{suffix}`, not `draft-{suffix}`.

Causal chain:

Draft creation writes `events.slug = draft-*`; later publish reuses `draft.serverSlug`; public route reads `events.slug`; the public link becomes `/e/{brand}/draft-*`.

Verification:

Read-only public view query returned `slug = draft-nlhj`, `title = Visa`, `status = scheduled`, `visibility = public`.

### F2 - The database forbids fixing the slug during publish

Severity: P0 architecture contradiction.

Evidence:

- `supabase/migrations/20260505000000_baseline_squash_orch_0729.sql:3300-3308` defines `biz_prevent_event_slug_change`.
- `supabase/migrations/20260505000000_baseline_squash_orch_0729.sql:12651-12655` installs `trg_events_immutable_slug`.

The trigger raises:

```text
events.slug is immutable (Cycle 7 share URLs depend on permanence; create a new event instead of renaming)
```

Current behavior:

The database treats the draft slug as already permanent.

Expected behavior:

Slug immutability should protect already-published URLs, not temporary draft placeholders. A draft should be allowed exactly one final slug assignment during an atomic draft-to-published transition.

Causal chain:

ORCH-0706 correctly froze public slugs for already-public events, but ORCH-0756B/0759 later introduced server drafts that need pre-public slugs. Those two contracts now conflict.

Fix direction:

Replace the trigger with a lifecycle-aware trigger that permits slug change only when:

- old row is `status = 'draft'`;
- new row is becoming `scheduled` or `live`;
- `published_at` was previously null;
- the slug is generated by the publish transaction/RPC.

After that transition, slug must remain immutable again.

### F3 - Publish explicitly preserves the draft slug

Severity: P0 confirmed bug.

Evidence:

- `mingla-business/src/services/eventDrafts.ts:173-184` updates the event on publish.
- `:177-180` chooses `draft.serverSlug` whenever it exists:

```ts
slug:
  draft.serverSlug !== null && draft.serverSlug.trim().length > 0
    ? draft.serverSlug
    : ...
```

Current behavior:

For normal server-backed drafts, `draft.serverSlug` exists, so publish keeps `draft-*`.

Expected behavior:

Publish should finalize the public slug from the final event title inside a server transaction, collision-check it, return it, and route/share with that returned value.

### F4 - Local published events mirror the same bad slug

Severity: P0 blast-radius amplifier.

Evidence:

- `mingla-business/src/utils/liveEventConverter.ts:70-74` generates a title slug, then discards it when `draft.serverSlug` exists.
- `:83` stores the chosen value as `liveEvent.eventSlug`.

Current behavior:

The local event cache and public server row agree, but they agree on the wrong thing: `draft-*`.

Why tests missed it:

The ORCH-0759 test contract says "local `LiveEvent.eventSlug === events.slug`." That passes when both are `draft-nlhj`. It does not assert "published slug must not be a draft placeholder" or "published slug derives from final title."

### F5 - Step 7 displays a non-final, non-clickable link

Severity: P1 UX / trust bug.

Evidence:

- `mingla-business/src/components/event/CreatorStep7Preview.tsx:145-149` passes `draft.serverSlug` into `ReadyCard`.
- `:186-188` builds the URL from that slug and strips `https://`.
- `:199-202` renders the URL inside plain `<Text>`, not a link, pressable, or copy action.

Current behavior:

Before publish, Step 7 can say:

```text
Tickets will go live at business.usemingla.com/e/leggothis/draft-nlhj.
```

That text is not clickable and is not the right public identity.

Expected behavior:

Before publish, either:

- do not show a final URL yet; say the public link will be created after publish; or
- reserve/finalize a real title-based slug safely on the server.

After publish, show a proper full URL with protocol plus explicit actions: Open public page, Copy link, Share.

### F6 - The public/share stack is now server-backed enough to expose the bad slug everywhere

Severity: P0/P1 blast radius.

Evidence:

- `mingla-business/app/e/[brandSlug]/[eventSlug].tsx` loads by slug through `usePublicEventBySlug`.
- `mingla-business/src/services/publicEventsService.ts:249-252` filters `business_public_events_view` by `brand_slug` and `slug`.
- `PublicEventPage` canonical/share/QR uses `eventPublicUrl({ brandSlug: event.brandSlug, eventSlug: event.eventSlug })`.
- Event Detail, Events tab, guest list, orders, checkout back-to-event, brand page cards, and SEO all use `event.eventSlug` or the route slug.

Current behavior:

Once the server row says `slug = draft-nlhj`, the whole public system faithfully shares `/draft-nlhj`.

Expected behavior:

The public stack should share the one durable final slug returned by an atomic publish.

## Required Fix Contract

### 1. Replace client-side publish with server-side atomic publish

Implement ORCH-0763's RPC direction:

```text
business_publish_event_draft(p_event_id uuid, p_draft_payload jsonb, ...)
```

The RPC must:

- lock the draft event row;
- validate caller role;
- verify `status = 'draft'`;
- generate the final slug from final event title;
- collision-check within the brand;
- replace/sync ticket rows;
- promote exactly one row to `scheduled`;
- remove `theme.business_draft`;
- return event, brand, and ticket rows.

### 2. Update slug immutability to be lifecycle-aware

Add a migration above current head `20260515000003`.

The trigger should allow exactly one slug change from draft placeholder to final public slug during publish. It should still reject slug changes after publish.

### 3. Stop preserving `draft.serverSlug` as the public slug

Remove the current publish behavior that uses `draft.serverSlug` as final truth.

Client publish must use the returned server event slug, not local `generateEventSlug`, not `draft.serverSlug`, and not `liveEventStore`.

### 4. Fix Step 7 link UX

Before publish:

- Do not show a final URL from `draft.serverSlug`.
- Show copy like "Your public link will be created after publish."

After publish:

- Show/open the returned full URL including `https://`.
- Provide explicit actions: Open public page, Copy link, Share.
- If URL text is visible, make it pressable/clickable on web and native.

### 5. Repair current bad public event rows

The production event `ecb4839f...` currently has `slug = draft-nlhj`.

After the lifecycle-aware slug migration lands, run an authorised recovery step to either:

- update this event to a title-based slug such as `visa-{suffix}` before broad sharing; or
- create an alias/redirect record so existing `draft-nlhj` links do not break if already shared.

This should be operator-approved because it mutates production event identity.

### 6. Add tests that catch this exact bug

Required regression tests:

- Server draft creation may use a draft placeholder, but publish must return a non-`draft` final slug.
- Publish final slug derives from event title and is brand-unique.
- Immutable slug trigger allows draft -> published finalization and rejects published -> changed.
- Client publish route/share uses returned server slug.
- Step 7 does not render `draft-*` as a public URL.
- Step 7 visible URL, if present, is actionable/copyable.
- `npm run test:orch-0759` or an ORCH-0763 test suite fails if a scheduled public event has `slug LIKE 'draft-%'`.

## Final Verdict

This is a real P0 event-publish contract bug.

The deploy fixed the old wrong-domain/404 class. The remaining failure is that "draft" is being treated as a permanent public identity. The correct fix is not a string patch in Step 7. It requires the ORCH-0763 publish repair: lifecycle-aware slug immutability, atomic server publish, returned canonical event payload, and post-publish clickable/copyable link UX.
